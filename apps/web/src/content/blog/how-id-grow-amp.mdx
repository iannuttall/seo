[Amp](https://ampcode.com/) is a coding agent. It runs in the terminal, in editors, in apps for Mac, iPhone and Android, and in orbs: cloud machines where every thread gets its own copy of your repository. It started inside Sourcegraph, and at the end of 2025 its founders spun it out as Amp Inc.

Amp makes money from plans. The free Hobby plan pays as you go for orbs. Megawatt costs $20 a month and includes 45,000 minutes of orb time, and Gigawatt is the bigger tier. Teams put members on those plans, and Enterprise is a sales conversation. Amp charges no token fees, and people can bring their own ChatGPT or Claude subscriptions.

So every visitor who matters is a developer choosing an agent, or a team choosing where its agents run.

Amp's search footprint is mostly one domain. I checked the others: www.ampcode.com, ampcode.net and Sourcegraph's old Amp address all redirect to ampcode.com, which is right. ampcode.app serves a full second copy of the site (more on that below). And Sourcegraph, now a separate company, still owns the pages for Cody, the assistant whose free and paid users it sent to Amp.

I crawled 600 sourcegraph.com pages to see how they link to Amp. There are 15 links in all, and 8 of them point at Amp's homepage with the link text "Amp". The Cody docs page, which Ahrefs estimates gets about 2,800 visits a month, has none.

## Three technical fixes, closest to revenue first

The crawl found three problems I'd fix. I've ordered them by how close each one sits to revenue.

### 1. ampcode.app serves a second copy of the site

ampcode.app returns the same pages as ampcode.com with a 200 status instead of redirecting, from the homepage to the docs. Most of them carry a canonical tag that points back to ampcode.com, which limits the damage. The pricing page has no canonical tag on either domain, so Google sees two equal copies of the page that sells the plans. Ahrefs has no keywords for ampcode.app yet, so this is a fix before it costs anything.

**The fix:** a permanent (301) redirect from every ampcode.app address to the same path on ampcode.com, set up as one rule at the CDN. Then add a canonical tag to the pricing page (and every other page without one) that names its own ampcode.com address. To confirm it worked, request ampcode.app/pricing and check the response is a 301, then check the pricing page in Search Console's URL Inspection, where the user-declared canonical should be the ampcode.com address.

## Get the changes seen quickly

The model pages are the biggest test here. Google has never been told about 109 of them, and a sitemap entry only asks it to visit when it gets round to it. I'd submit every new and changed URL to [Index My Site](https://indexmysite.app/) the day it ships, so Google is asked to crawl it straight away. That matters most for the model pages, the retitled orbs page and the new comparison pages, where nothing can move until Google has seen them.

## How I ran this

Everything in this teardown came from SEO Skill, run by an agent. You can run the same audit on your own site.

**1. Connect the hosted MCP server.** It's free. You sign in with Google, and there's no password and nothing to install. In Claude Code:

```sh
claude mcp add --transport http seoskill https://seoskill.dev/mcp
```

Codex, Cursor and Claude on the web work too. The [MCP guide](/docs/mcp) has the steps for each one.

**2. Add a research key.** On your [account page](/account), save an Ahrefs or DataForSEO key. The key gives your agent search volumes, rankings and results pages, like the tables above.

**3. Install the CLI for crawling.** The crawl runs on your machine, so it can read any site:

```sh
npm i -g seo
seo login
```

**4. Ask your agent.** This is close to the prompt I used:

```text
Audit example.com and every domain we own.
Follow redirects from our old and sister domains.
Crawl each one with seo crawl, and check what
unknown addresses and the sitemap return.
Use seo_research to find the searches our buyers
make, who ranks for them and whether we can compete.
Rank every fix by how close it sits to revenue.
```

On your own site, the hosted server adds the part I couldn't see from the outside: your real Search Console clicks and queries. With those, you get measured numbers where this post has estimates.

Check every domain that leads to you, too. Two of the fixes in this teardown came from addresses nobody looks at: a second domain and a hundred pages Google was never told about.
