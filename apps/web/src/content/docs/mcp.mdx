There is nothing to install and no password to create. Your agent connects to `https://seoskill.dev/mcp`, you sign in with Google once, and the tools read your own data on each request.

## Add the server

Claude Code:

```sh
claude mcp add --transport http seoskill https://seoskill.dev/mcp
```

Codex:

```sh
codex mcp add seoskill --url https://seoskill.dev/mcp
```

Cursor, in `.cursor/mcp.json` or `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "seoskill": { "url": "https://seoskill.dev/mcp" }
  }
}
```

Claude on the web or desktop: open Settings, then Connectors, add a custom connector, and enter `https://seoskill.dev/mcp`.

Other clients: add a remote MCP server with the same URL.

## Sign in with Google

The first time your client connects, your browser opens a sign-in page. Continue with Google and allow read-only access to Search Console and Google Analytics. You need access to at least one Search Console property.

That first Google account is your account. Sign in with it on your [account page](https://seoskill.dev/account) to add more.

## Manage your account

Your [account page](https://seoskill.dev/account) is where you:

- add another Google account, such as a client's or a work account,
- save DataForSEO or Ahrefs keys (the [API keys guide](/docs/keys) explains them),
- delete everything, or sign out.

Each request uses the linked Google account that can read the site. If none can, the error names your linked accounts and links to the account page.

## Tools your agent gets

| Tool | What it returns |
| --- | --- |
| `seo_sites` | The Search Console and Google Analytics properties your linked Google accounts can read, and which keys are set. |
| `seo_report` | The [main report](/docs/report). An overview first, then one section. |
| `seo_page` | [One URL](/docs/page): live page facts, Google index status and its queries. |
| `seo_compare` | [Before and after a date](/docs/compare), with Google updates in the window. |
| `seo_index` | [Pages that lost their clicks](/docs/indexing), checked live and with URL Inspection. |
| `seo_research` | [Keyword and competitor data](/docs/research) from your own provider key. |
| `seo_data` | [Raw rows](/docs/data) from Search Console, or Google Analytics and Clicky landing pages. |

Each tool takes a site or URL and optional dates. Results start as a short summary, and your agent can ask for more rows when it needs them. Every result names the tool to run next.

The site crawl, internal links, [Bing Webmaster Tools](/docs/bing), and analytics tools other than Google Analytics and Clicky run on your own machine, so they are only in the [CLI](/docs/cli). The hosted server tells your agent to use the CLI for them.

## What the server keeps

Only your linked Google and Bing accounts, any keys and Clicky sites you save, encrypted, and the names of the machines you link. They are used to fetch your own data when your agent asks. The server keeps no reports, no Search Console or analytics rows, no site lists and no request logs. The token your agent keeps holds only a random person id.

The only other thing kept is an anonymous count of what ran: the event, report, agent, version and week. [What is stored](/docs/privacy) has the details.

## Remove access

Sign in on your [account page](https://seoskill.dev/account) and choose **Delete everything**. It deletes your linked accounts and keys and revokes the Google sign-ins, so your agents will ask you to sign in again. Then remove the server from your agent.

You can also revoke SEO Skill in your [Google account connections](https://myaccount.google.com/connections). That stops the stored Google tokens working.
