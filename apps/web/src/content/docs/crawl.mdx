Use it to get a technical baseline: before a release, after one, or when you suspect something broke across many pages. A crawl fetches a lot of pages, so it runs on your machine with the [CLI](/docs/cli), not on the hosted server.

## Run a crawl

Install the CLI and run setup if you have not yet:

```sh
npm i -g seo && seo start
```

Then ask your agent to crawl the site, or run it yourself:

```sh
seo crawl https://example.com
```

The crawl stops at 500 pages unless you raise `--max-pages` (up to 10,000). When your sitemaps list more pages than that, the crawl does not just take the first ones. It takes pages in turn from each section of the site (`/blog`, `/docs`, `/forum` and so on), so a big forum cannot crowd out your product pages, and the result says how it picked them. For a large site, start with a quick sitemap pass that checks status codes and redirects without reading every page:

```sh
seo crawl --sitemap-url https://example.com/sitemap.xml --health
```

## What comes back

The crawl fetches your pages and lists what it finds, such as pages that return errors, redirects, missing or duplicate titles and descriptions, canonical and robots tags, and broken internal links. Nothing is saved: the result comes back in full, and your agent keeps what it needs (add `--json --output crawl.json` to write it to a file).

Googlebot reads only the first 2 MB of a page's HTML and indexes it as if the file ended there. For a page over that size, the crawl shows where the main content starts (the first `<h1>` or `<main>`) and how much of the page sits past the cut. It flags the page as high priority when the main content starts after the cut or just before it, or when most of the visible text comes after it.

A `noindex` tag or a canonical pointing elsewhere is reported as what the page says. It is only a problem if you did not mean it.

## What AI agents can read

The crawl also checks how AI agents get to your site:

- Which AI search bots (such as OAI-SearchBot, Claude-SearchBot and PerplexityBot) and which AI training bots (such as GPTBot and ClaudeBot) your robots.txt allows. The two groups are listed apart, because blocking training is a choice and blocking search keeps you out of AI answers.
- Whether your pages have a Markdown copy: through a `rel="alternate"` link, or for a request with `Accept: text/markdown`. Every public page can have one, including noindex pages such as privacy and terms. The crawl reports a page that needs a sign-in and still links to a copy.
- Whether `/llms.txt` exists and its links load.
- Agent files under `/.well-known/`, such as an agent skills index or an MCP server card, plus the `Content-Signal` and `Link` headers.

None of these change your Google rankings. They decide how easily ChatGPT, Claude and other agents can read and quote you. If a file could not be fetched, the crawl says so instead of calling it missing.

## Check many sites at once

To compare robots.txt, home pages and llms.txt across many sites, such as a list of competitors, use sites mode. It reads up to 1,000 sites a run, eight at a time, with three requests per site: robots.txt, the home page (unless robots.txt disallows it), then llms.txt.

```sh
seo crawl --mode sites --urls-file sites.txt --json --output sites.jsonl
seo crawl --mode sites --urls example.com,example.org
```

Each site is one JSON line with its robots.txt rules for each AI bot, the home page's status, title, canonical and robots tags, and whether llms.txt exists and starts with a heading. A last line sums the run. Without `--json` you get the counts, such as how many sites block GPTBot. A site that timed out, failed DNS or served a challenge page says so, so an unreachable llms.txt is never counted as missing.

To see which pages lost search clicks rather than which pages have issues, use [`seo index`](/docs/indexing).
