## Google Search ignores llms.txt

Google's [AI optimization guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) is blunt about it. You don't need "new machine readable files, AI text files, markup, or Markdown to appear in Google Search (including its generative AI capabilities), as Google Search itself doesn't use them." It lists llms.txt among the "AEO/GEO hacks" you can ignore for Google.

So llms.txt is not a ranking factor, and it won't get you into AI Overviews or AI Mode. The same guide also says it's "completely fine" to keep one "for other services or systems that use these files." That line matters more, because Google isn't the only reader.

## AI crawlers read Markdown copies, not llms.txt

Rankera counted the successful requests for llms.txt and Markdown copies (`.md` files) on 517 content sites in its own publishing network from 17 to 23 October 2026, from Cloudflare's request logs. The [case study](https://rankera.ai/llms-txt-case-study) is the largest public count I've found.

Most of llms.txt's 4,695 requests that week came from SEO tools (2,380, mostly SEOJuice) and from visitors with ordinary browser user agents (1,908). AI-visibility checkers asked for it too. The AI companies' own crawlers asked for it 24 times.

The Markdown copies don't keep that pull. Three weeks later, from 2 to 8 November, AI crawlers made 18,221 requests for the same `.md` files, 64% fewer, while all AI crawling on the 479 sites Rankera tracked every day rose 19%. Rankera reads it as a one-time discovery crawl when the copies went up. And a crawl is not a citation. Most of these requests came from crawlers that collect training data.

The assistants that open pages while answering someone (ChatGPT-User, Claude-User, Perplexity-User and DuckAssistBot) made 55,310 live fetches that second week. 42 were for a `.md` file. None were for llms.txt. They read the normal page.

## Agents on a task do open llms.txt

The agent that reads llms.txt is the one sent to a site with a job, such as "find how this API authenticates" or "compare these two plans". Vercel and the ora.ai research lab traced 1,033 of those runs across 25 sites between June and August 2026, and published [the guide](https://vercel.com/kb/guide/make-your-site-readable-by-ai-agents) with the data.

- Agents reached llms.txt in 329 runs. 120 of those runs drew the final answer from it.
- 86% of llms.txt fetches (356 of 416) arrived through a link, not a guessed path, so link yours.
- 65.1% of web fetches (2,259 of 3,470) asked for Markdown.

Six sites (Zapier, monday.com, Telnyx, Attio, ora.ai and Stripe) make up 66.9% of those runs (691 of 1,033), so this is mostly how agents read docs-heavy software sites. That's also where llms.txt is used most, according to [the proposal](https://llmstxt.org/). Coding agents ask for Markdown outright, too. Cloudflare [says](https://blog.cloudflare.com/markdown-for-agents/) Claude Code and OpenCode send an `Accept: text/markdown` header with their requests.

The same study has a line that cuts the other way. In its controlled tests, adding llms.txt, Markdown mirrors, JSON-LD or a sitemap "did not change whether the clients could retrieve an answer already present in server-rendered HTML." llms.txt helps an agent find the page. It can't stand in for the page.

## JavaScript hides more from agents than a missing llms.txt

If your pages are drawn by JavaScript, llms.txt is the wrong thing to worry about. Vercel's [crawler study](https://vercel.com/blog/the-rise-of-the-ai-crawler) from December 2024 found that "none of the major AI crawlers currently render JavaScript". That covers OpenAI's three crawlers, ClaudeBot, Meta's crawler, Bytespider and PerplexityBot. Googlebot and Applebot do run it. ChatGPT's and Claude's crawlers fetched the JavaScript files and didn't run them.

## What I'd set up for AI agents

None of this needs to be clever. In order of what it's worth:

<PlanSteps
  steps={[
    { title: "Put every answer in the HTML", body: "Prices, plan limits, specs and FAQ answers in the server-rendered page, not loaded by JavaScript or hidden behind a tab that fetches on click." },
    { title: "Serve a Markdown copy of each page", body: "At the same address plus .md, linked from the page with <link rel=\"alternate\" type=\"text/markdown\">. If you can, also return it for requests that send Accept: text/markdown, with a Vary header set to Accept so caches keep the two apart." },
    { title: "Keep llms.txt short and linked", body: "A heading, one line on what the site is, then the pages that sell and the docs that answer, each with a line about it. Link it from your pages, in the footer or with <link rel=\"describedby\" href=\"/llms.txt\"> in the head, so agents find it without guessing." },
    { title: "Check it like any other page", body: "Broken links in llms.txt and Markdown copies that 404 send agents to dead ends. Crawl them with the rest of the site." },
  ]}
/>

This is how seoskill.dev does it. Every page has a Markdown copy, and a request that asks for Markdown gets it:

```sh
curl -sI -H "Accept: text/markdown" https://seoskill.dev/blog/webmcp
HTTP/2 200
content-type: text/markdown; charset=utf-8
vary: Accept
```

Its [llms.txt](/llms.txt) opens with the product, pricing and getting-started pages before the docs, because agents don't only come for the API reference. If you're starting from nothing, the [llms.txt generator](/tools/llms-txt-generator) builds the file from links you choose.
