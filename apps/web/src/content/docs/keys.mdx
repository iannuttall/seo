Search Console and Google Analytics come with your Google sign-in. Everything else is optional and uses a key from your own account, so the provider bills you directly for what you use.

## What each key adds

| Provider | What it adds | Tool |
| --- | --- | --- |
| DataForSEO or Ahrefs | Keyword metrics, ranked keywords, SERPs, competitors and backlinks | `seo_research` |
| Clicky, Fathom, Simple Analytics or Plausible | Landing pages for visits from search | `seo_data` |

Research rows also get a free Domain Rating column, with no key needed. It is Domain Rating by [Ahrefs](https://ahrefs.com).

## Add keys on the sign-in page

This works in every client.

1. Remove the SEO Skill server from your agent, then add it again with `https://seoskill.dev/mcp`.
2. On the sign-in page, open **Add your own API keys** and enter the keys you want.
3. Continue with Google.

The keys are sealed into the sign-in your agent keeps. To change them, connect again.

## Or send keys as headers

Clients such as Claude Code, Codex, Cursor and VS Code can send headers with each request. A header wins over a key from the sign-in page.

```sh
claude mcp add --transport http seoskill https://seoskill.dev/mcp \
  --header "X-Ahrefs-Key: ${AHREFS_API_KEY}"
```

| Provider | Headers |
| --- | --- |
| DataForSEO | `X-DataForSEO-Login`, `X-DataForSEO-Password` |
| Ahrefs | `X-Ahrefs-Key` |
| Clicky | `X-Clicky-Sitekey` |
| Fathom | `X-Fathom-Key` |
| Simple Analytics | `X-Simple-Analytics-Key`, optional `X-Simple-Analytics-User-Id` |
| Plausible | `X-Plausible-Key` |

Keep keys in your shell environment or keychain. Never paste one into a chat or commit it to a repository.

## How keys are handled

A key arrives sealed inside your sign-in token or as a header on the request. The server uses it for that request only and never saves it. The [what is stored page](/docs/privacy) covers the rest.

The server also has its own short [key setup page](https://seoskill.dev/mcp/keys) if your agent needs a link to give you.
