## What you need before the first prompt

You need Claude Code or Codex and a Google account that can read your site's Search Console property. SEO Skill gives either agent your Search Console data, read only, through a free hosted MCP server. You don't set it up by hand. The first step below has a setup prompt for your agent. The agent adds the hosted MCP server, waits while you sign in with Google, then installs the CLI and the skill. The skill tells the agent which tool answers which SEO question. The CLI runs the jobs the hosted server can't, such as a site crawl and Bing. In Codex you can name the skill with `$seo` in a prompt to make sure it loads. The [Claude SEO skill](/features/claude-seo) and [Codex SEO skill](/features/codex-seo) pages cover each agent in more detail.

## Ask the agent what's due first

I started the way the [`seo next`](/docs/next) docs suggest, by asking the agent to work on the site rather than asking for a particular report. Every prompt below uses example.com; swap in your own site.

It came back with one step and the pages to work on:

- Improve the pages that rank: 22 open.

| kind       | subject                                   | evidence                                          |

| index-drop | /tools/word-combiner                      | dropped out 2026-11-14, Crawled - currently not indexed |

Four pages had dropped out of Google's index between 14 and 16 November 2026. That's the right thing to fix first, and it's a job I'd hand to the agent with a pull request at the end. One of the four says "Excluded by 'noindex' tag", which may be deliberate, so I'd want the agent to ask before it touches that tag. Those four are a separate job. This session is about the step after it, improving pages that already rank.

Thirteen of the 17 rows were on the SERP checker tool and carried a "likely-automated" flag. Those searches follow the pattern of rank tracker tests, so they probably came from software rather than people. An agent working alone could easily rewrite a page for bots. The flag is there so it doesn't, but it's still worth a glance from you.

The top real row was "ai seo skill", with 172 impressions for the home page at an average position of 7.74 and no clicks. The home page title is "SEO Skill | Open source SEO for agent-native teams". The obvious move, and the one this row invites, is a new home page title with "AI SEO skill" in it.

## Check the page Google should have picked

When the right page gets nothing, the first question is what Google has on file for it.

<AgentStep prompt="Check example.com/features/claude-seo: is it indexed, when did Google last crawl it, and what does it rank for?" />

```text
title: Claude SEO skill for Claude Code and Claude.ai | SEO Skill
h1: Claude SEO skill
verdict: PASS | Submitted and indexed | last_crawl 2026-11-03T15:28:28Z
Query totals: clicks 0, impressions 1.
```

The page is indexed and its title matches the searches. But Google last crawled it on 3 November 2026, and the page was rebuilt on 11 November 2026. Google is judging a version of the page that no longer exists.

## The fix: send Claude searches to the Claude page

I wouldn't retitle the home page for Claude. It serves every agent, and I'd rather not have two pages chasing the same searches. The Claude SEO skill page is the better answer for someone who searched "claude seo skill", so the job is to get Google to see it.

Two changes, both small:

1. Request indexing for the Claude SEO skill page with Search Console's [URL Inspection tool](https://support.google.com/webmasters/answer/9012289), so Google crawls the rebuilt version. Google says indexing "typically takes only a day or so" but doesn't guarantee it.
2. Link to it from the home page in words that say what it is. The home page linked it only from its list of features. The card for founders who build with agents already named Claude Code and Codex, and linked to the getting started guide.

## What to let the agent do alone, and what to check yourself

My rule is simple. Let the agent do the data work, which means pulling the rows, running the checks again, cross-checking a SERP and drafting the change. Keep the decisions about what ships, and what the page says, with a person.

| Let the agent do it | Check it yourself |
| --- | --- |
| Pull the report, the quick wins and the raw rows | Whether a query is really looking for you, like "ai-seo skill" |
| Flag rank tracker noise and leave it out | Any change to a page that brings most of your clicks |
| Check index status and last crawl dates | Removing a noindex, a redirect or a deleted page |
| Find the file that sets a title and draft the diff | The words on the page and in the title |
| Run the same check again after the fix | Whether a change in the numbers is the fix or something else |

In this session the agent found every number. It also proposed the wrong first fix, and only the SERP and the title history showed why. That's the part I'd keep for myself.

## Run the same session every week

The session is most useful run the same way each week, because the agent can then tell you what changed. Ask it the same first question:

<AgentStep prompt="Use SEO Skill to work on example.com. What changed since last week, and what's due?" />

SEO Skill keeps a list of issues for each site between sessions. When a change is live, mark it fixed, and the list later shows that page's clicks and impressions for the 28 and 56 days after the fix against the same days before:

<AgentStep prompt="The new title for the pricing page went live today. Mark that issue fixed on example.com." />

Keep the windows comparable from week to week, such as the last 28 days against the 28 before, so a change in the numbers isn't a change in the dates. You can schedule the prompt in your agent or run the CLI from a scheduled job; the [cloud agents guide](/docs/cloud-agents) covers machines that start fresh each time. The paid [weekly site audit](/docs/weekly-site-audit), $50 a month per site, runs the crawl and daily index checks in the background if you'd rather not schedule anything.

Start with the step `seo next` says is due. On seoskill.dev that was four pages out of Google's index, and I'd fix those before any title.
