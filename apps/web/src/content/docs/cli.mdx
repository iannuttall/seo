Use the CLI when you want everything local, when you script reports, or when you need the two commands that fetch many pages from your machine.

## Install and run setup

You need Node 22 or newer.

```sh
npm i -g seo && seo start
```

The first part installs the package. `seo start` then runs setup.

Setup walks you through three things:

1. Sign in. If you already have a seoskill.dev account, sign in to it, or create one: it holds your Google accounts, Bing and keys for both the CLI and the hosted MCP. You can also sign in with Google on this machine only. Either way, Search Console and Google Analytics access is read-only.
2. Add an MCP server to the agents it finds on your machine. The free [hosted server](/docs/mcp) is the first choice; the local one runs on your machine with this sign-in. Claude Desktop takes the hosted server only from its Connectors settings, so setup gives it the local one.
3. Install the skill, which teaches your agent the commands.

If you skip a step, you can do it later with `seo mcp install` or `seo skill install`. Setup saves nothing about your site, so each command names the site it works on. To see the sites your sign-in can read:

```sh
seo sites
```

## Use your seoskill.dev account

If you use the [hosted MCP](/docs/mcp), link the CLI to the same account. Your Google accounts, Bing and research keys then live in one place, and every machine you link uses them:

```sh
seo login
```

It opens a page on seoskill.dev where you approve this machine. The CLI then asks the account for short-lived tokens and makes the Google and Bing requests itself (Bing blocks the hosted server, so this is how Bing works with an account). Nothing it fetches goes back to seoskill.dev. Your linked machines are listed on your [account page](https://seoskill.dev/account), where you can remove them. `seo logout` unlinks this one.

## Run the commands

| Command | What it does |
| --- | --- |
| `seo report` | The [main report](/docs/report), an overview first, then one section |
| `seo page` | [One URL](/docs/page): live page facts, Google index status and its queries |
| `seo compare` | [Before and after a date](/docs/compare), with Google updates |
| `seo index` | [Pages that lost their clicks](/docs/indexing), checked live |
| `seo research` | [Keyword and competitor data](/docs/research) from your own key |
| `seo data` | [Raw Search Console rows](/docs/data) for any dimensions |
| `seo crawl` | [Crawl your site](/docs/crawl) and list technical issues |
| `seo internal-links` | [Internal links to add](/docs/internal-links) across a site or to one page |

A few examples:

```sh
seo report --site example.com
seo report --site example.com --section quick-wins
seo page --url https://example.com/pricing
seo compare --site example.com --date 2026-09-15
```

Add `--json` to any of them for structured output, or `--help` to see every option.

Research needs a provider key. Keys saved on your [account page](https://seoskill.dev/account) work once you run `seo login`. To keep a key on this machine only instead:

```sh
seo providers dataforseo connect
```

## Coming from an older version

Saved projects are gone, so pass `--site` instead of `--project`. Commands that saved history between runs, such as `seo change-log`, `seo technical-watch` and `seo crawl-reports`, were removed (your agent keeps its own notes now). Removed commands and flags stop with a short message that names what to use instead.

The old report names, such as `seo quick-wins`, still run and print the new command to use. To stay on the old version, run `npm i -g seo@0.2.41`.

Your agent runs the same commands for you once setup has added the skill, so most days you just ask it a question.

## Run it in a cloud agent

On a machine that is rebuilt each time, such as Amp, Codex cloud or CI, make a token on your [account page](https://seoskill.dev/account) and save it as the `SEO_TOKEN` secret. The CLI then uses your account with no login step. The [cloud agents guide](/docs/cloud-agents) has the details.

## Where your data lives

Your Google tokens, settings, keys and a short cache of responses stay on your machine. Reports and crawls are not saved. Nothing is sent to SEO Skill except the [anonymous usage counts](/telemetry), which you can turn off:

```sh
seo telemetry disable
```
