There is nothing to install and no password to create. Your agent connects to `https://seoskill.dev/mcp`, you sign in with Google once, and the tools read your own data on each request. The [Google Search Console MCP](/features/search-console) page shows the questions it answers from Search Console.

## Set it up with one prompt

Give your agent this prompt. It adds the server, waits while you sign in with Google and checks the tools load. It also installs the CLI and the skill.

## Add the server by hand

Claude Code:

```sh
claude mcp add --transport http --scope user seoskill https://seoskill.dev/mcp
```

The [Claude SEO skill](/features/claude-seo) page adds the skill and the CLI next to the server.

Codex:

```sh
codex mcp add seoskill --url https://seoskill.dev/mcp
```

The [Codex SEO skill](/features/codex-seo) page covers the sign-in, the skill and the CLI in Codex.

Cursor, in `.cursor/mcp.json` or `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "seoskill": { "url": "https://seoskill.dev/mcp" }
  }
}
```

Claude on the web or desktop: open Settings, then Connectors, add a custom connector, and enter `https://seoskill.dev/mcp`.

Other clients: add a remote MCP server with the same URL.

## Sign in with Google

The first time your client connects, your browser opens a sign-in page. Continue with Google and allow read-only access to Search Console and Google Analytics. You need access to at least one Search Console property.

That first Google account is your account. Sign in with it on your [account page](https://seoskill.dev/account) to add more.

## Manage your account

Your [account page](https://seoskill.dev/account) is where you:

- add another Google account, such as a client's or a work account,
- save DataForSEO or Ahrefs keys (the [API keys guide](/docs/keys) explains them),
- delete everything, or sign out.

Each request uses the linked Google account that can read the site. If none can, the error names your linked accounts and links to the account page.

## Tools your agent gets

| Tool | What it returns |
| --- | --- |
| `seo_sites` | The Search Console and Google Analytics properties your linked Google accounts can read, and which keys are set. It can also add a site to the [weekly site audit](/docs/weekly-site-audit) when you ask. |
| `seo_next` | [The next step](/docs/next) in the SEO loop for a site, with its first jobs. |
| `seo_report` | The [main report](/docs/report). With a site, an overview first, then one section. With no site, last week across the sites in your [weekly site audit](/docs/weekly-site-audit). |
| `seo_page` | [One URL](/docs/page): live page facts, Google index status and its queries. |
| `seo_compare` | [Before and after a date](/docs/compare), with Google updates in the window. |
| `seo_index` | [Google's indexing reasons](/docs/indexing) for your pages, checked live and labelled, and pages that lost their clicks. |
| `seo_submit` | [Ask search engines to crawl pages](/docs/submit): IndexNow keys for Bing and others, or Index My Site for Google from your own credits. It shows the cost before it sends anything. |
| `seo_research` | [Keyword and competitor data](/docs/research) from your own provider key. |
| `seo_data` | [Raw rows](/docs/data) from Search Console, or Google Analytics, Clicky and Simple Analytics landing pages. |
| `seo_lint` | [Lines in your copy](/docs/lint) that read as AI-written, each with a fix. |

Most tools take a site or URL and optional dates. Results start as a short summary, and your agent can ask for more rows when it needs them. Every result names the tool to run next.

The site crawl, internal links, [Bing Webmaster Tools](/docs/bing), and analytics tools other than Google Analytics, Clicky and Simple Analytics run on your own machine, so they are only in the [CLI](/docs/cli). The hosted server tells your agent to use the CLI for them.

## What the server keeps

Only your linked Google and Bing accounts, any keys, Clicky sites, Clicky account login and Simple Analytics key you save, encrypted, and the names of the machines you link. They are used to fetch your own data when your agent asks. It also keeps, for any site you use it on, the issues list your agent asks for with the `issues` section of the [report](/docs/report#keep-a-list-of-issues) and the business context it saves with [`seo next`](/docs/next). Otherwise the server keeps none of your reports, Search Console or analytics rows, site lists or request logs, except what the paid weekly audit keeps for its sites. The token your agent keeps holds only a random person id.

The only other thing kept is an anonymous count of what ran: the event, report, agent, version and week. [What is stored](/docs/privacy) has the details.

## Remove access

Sign in on your [account page](https://seoskill.dev/account) and choose **Delete everything**. It deletes your linked accounts, keys, issues lists and business context, and revokes the Google sign-ins, so your agents will ask you to sign in again. Then remove the server from your agent.

You can also revoke SEO Skill in your [Google account connections](https://myaccount.google.com/connections). That stops the stored Google tokens working.
